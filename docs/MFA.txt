**용어 정리**
모놀리식
" 한 저장소에 하나의 앱과 관련된 모든 코드와 리소스를 넣는 방식 "
모듈러 레포
" 소스 코드를 분류하여 여러개의 모듈로 나누고 모듈을 각각의 패키지로 만들어 필요한 패키지를 가져다 쓰는 방식 "
- 패키지간의 정의된 관계가 없다면 MONOREPO가 아니고, 이러한 패키지를 잘 관리하며 하나의 레포에서 관리하면 MONOREPO 이다.
멀티레포(=폴리레포)
" 모듈로 나누어 모듈마다 레포를 가지고 관리하는 방식 "
- 단점 : 히스토리를 추적하기 어렵다. 프로젝트 설정이 일관적이지 못하다. 기존 코드 활용성이 낮다.
- 장점 : 의존성이 낮다. ci/cd가 간편하다.. 저장소가 가볍다.
모노레포(=하나의 레포에서 관리하는 모듈러 레포)
" 잘 정의된 관계를 가진 여러개의 개별 프로젝트가 포함된 단일 레포지토리"
- 단점 : 과도한 의존성, 복잡한 ci/cd, 저장소가 무겁다.
- 장점 : 히스토리를 추적하기 쉽다. 일관된 프로젝트 설정이 가능하다. 기존 코드를 활용할 수 있다.

** 서비스 아키텍처**
MFA 기본 개념
- 독립적으로 제공 가능한 앱
- 독립적으로 개발 및 운영이 가능한 앱
- 여러개의 마이크로 앱을 합쳐 커다란 앱을 운영
(빌드를 끝낸 앱들을 합쳐 운영하는건.. MFA라고 보기 어렵다. 빌드까지 동시에 한앱에서 실행하는것까지 구성으로 본다.)

BFF (Backend For Frontend) 기본 개념
- 각 프론트엔드 앱에 해당하는 프론트 요구사항을 충족하는 백엔드가 있는 패턴

>> 현실적으로 바로 전환이 어려울수 있기에, BFF 같은 레이어를 활용해서 점진적으로 변해가기도 한다.
